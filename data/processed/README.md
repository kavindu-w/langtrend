# data/processed

Everything derived from `data/raw/` — manifests, taxonomy, and the small summary artifacts that back the README and the website. All committed unless noted otherwise.

```text
data/processed/
├── langtrend_manifest_last_7_days.json   "Latest" manifest pointer
├── language_data.json                    Language class taxonomy
├── language_screening_warnings.json      Acronym/language-name conflicts
├── weekly_summary.csv                    One row per week, counts only
├── weeks/                                Per-week archive (see weeks/README.md)
└── badges/                               Shields.io badge JSON (see badges/README.md)
```

| Path | Contents |
|------|----------|
| `langtrend_manifest_last_7_days.json` | Copy of the most recently built weekly manifest — the "latest" pointer the website and `scripts/update_readme_stats.py` read, so callers don't need to know the current week's date range. |
| `language_data.json` | Language class taxonomy (`lang_classes`, `languages_to_ignore`, `possible_false_positive_languages`), regenerated from the `Some-Languages-are-More-Equal-than-Others` submodule by `scripts/extract_language_data.py`. |
| `language_screening_warnings.json` | Acronym/language-name conflicts suppressed during detection (e.g. a paper defining "MAE" near a mention of Mae) — surfaced on the website as a transparency/false-positive warning list. |
| `weekly_summary.csv` | One flat row per week (dates, paper/flagged/unique-language counts, per-class counts) — a small table-ready alternative to parsing every week's full `langtrend_manifest.json`. Regenerated by `scripts/update_readme_stats.py`. Column reference below. |
| `weeks/` | Per-week archive — one subdirectory per processed week. See `weeks/README.md`. |
| `badges/` | Shields.io endpoint JSON consumed by the root README's badge row. See `badges/README.md`. |

### `weekly_summary.csv` columns

One row per processed week, ordered oldest → newest. All counts are for that week only (not cumulative).

| Column | Meaning |
|--------|---------|
| `week_start`, `week_end` | The week's date range (matches the `weeks/<week_start>_to_<week_end>/` folder name). |
| `papers` | Total papers scanned that week (arXiv `cs.CL` submissions in the window). |
| `flagged_papers` | Papers where at least one language was detected (abstract, HTML sections, or PDF fallback). |
| `unique_languages` | Count of **distinct** languages detected that week. |
| `total_language_mentions` | Total language **detections** that week — the sum of `class_0_mentions`..`class_5_mentions`. A paper mentioning 3 languages contributes 3 to this total but 1 to `flagged_papers`, so it's always ≥ `flagged_papers` and ≥ `unique_languages`. |
| `top_language` / `top_language_count` | The single most-mentioned language that week, and how many papers mentioned it (ties broken alphabetically). |
| `needs_review_detections` / `needs_review_papers` | How many detections (and distinct papers) were flagged `needs_review` — likely false positives such as a short language name colliding with a common ML acronym (see the root README's "Transparent false-positive handling" bullet). Not excluded from the other counts, just flagged for manual spot-checking. |
| `class_0_mentions` .. `class_5_mentions` | Detection counts (not unique papers or unique languages — see `total_language_mentions` above) grouped by the Joshi et al. resource-availability class from the root README's "Language Classes" table: `class_0_mentions` = exceptionally limited resources (e.g. Pinyin, Irarutu) through `class_5_mentions` = dominant, massively-resourced languages (e.g. Arabic, Chinese, English). A paper mentioning both English (class 5) and Sinhala (class 2) adds 1 to `class_5_mentions` and 1 to `class_2_mentions`. |
| `pdf_failed_no_detection` | Papers with no HTML version where the PDF also failed to download, so only the abstract could be scanned and nothing was detected. |

`weekly_summary.csv`, `badges/*.json`, and the root `README.md`'s "Latest Run Summary" table are all regenerated together by `scripts/update_readme_stats.py` (`make readme-stats` locally, or automatically in CI — see `.github/workflows/langtrend.yml`, job `pdf-retry-2`).
