# data/processed/badges

Shields.io ["endpoint" badge](https://shields.io/badges/endpoint-badge) JSON, read by the two custom badges in the root README's badge row (`Papers Analysed`, `Languages Tracked`) via `https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/kavindu-w/langtrend/main/data/processed/badges/<file>`.

```text
data/processed/badges/
├── papers_badge.json      "Papers Analysed" badge
└── languages_badge.json   "Languages Tracked" badge
```

| File | Badge | Schema |
|------|-------|--------|
| `papers_badge.json` | Papers Analysed | `{"schemaVersion": 1, "label": "papers analysed", "message": "<all-time paper count>", "color": "0f6c5d"}` |
| `languages_badge.json` | Languages Tracked | `{"schemaVersion": 1, "label": "languages tracked", "message": "<all-time unique language count>", "color": "0f6c5d"}` |

Both are regenerated by `scripts/update_readme_stats.py` from the cumulative counts across every week in `data/processed/weeks/` — don't edit them by hand, they'll be overwritten on the next run (`make readme-stats` locally, or automatically in CI). Note shields.io caches `/endpoint` responses for roughly 2 hours, so the badge on GitHub may lag slightly behind a fresh push.
